## 1. 目标与非目标

**目标**（验收见 §9）：
1. 语义检索翻出对的记忆：搜「番茄」出园艺记忆；搜库里没有的话题返回明确的空。
2. 消灭四个结构病：藤蔓搭车不看查询、检索刷 updated_at 富者愈富、vault 无垃圾线、化石 _score。
3. 记忆不再静默隐形：向量写入可靠 + 缺失补齐 + 删除同步删向量。
4. 过时信息可作废：supersede 状态 + 全召回路径 LIVE 过滤 + 待审队列（人拍板）。
5. 额度解锁：Workers Paid，全量语义覆盖，预算闸补到所有路径。
6. 检索可解释：recall_trace 留痕，以后调阈值靠数据。
7. 新能力：情绪共鸣通道、独处/做梦选材配方、密钥脱敏、周巡检报告。

**非目标/禁改**：
- **手写 vault 的内容与语义神圣**：不去重、不衰减、不自动 supersede、不自动改写。机器只能"提议"，落字的只有静怡和她明示的操作。
- 不引入 VPS、不引入第三方管家 LLM、不做逐条消息的 LLM rerank/query expansion。
- 不动聊天主流程、动态流、relay 桥、独处/做梦前端的既有行为（除本文明确列出的接线点）。
- 旧代码迁移逐字照搬原则不变。

## 批1：检索引擎重构（核心，1-2 天，worker.js）

### 1.1 memory_search 语义模式 → 多通道 RRF 融合

废弃 `searchA` 的加权公式（`vScore*0.45+kScore*0.15+tScore*0.15+rScore*0.15+iScore*0.1`），改为：

1. **各通道独立出榜**（每通道先过自己的垃圾线）：
   - `vector`：余弦排序，**dist>0.50 硬丢弃**，且丢弃 dist>best+0.12 的（相对窗）。权重 1.0。
   - `keyword/FTS`：现有子串/标签匹配逻辑保留，按词频排序。权重 1.0。
   - `vine`（藤蔓）：见 1.2。权重 0.8。
   - `emotion`：见批5（先留接口，通道为空）。权重 0.5。
2. **RRF 融合**：`score = Σ 1/(60+rank_c) × weight_c`，同一条记忆被多通道命中则**相加**（交叉验证加分）。
3. **重要度/唤醒度/激活数一律不进第一段排序**。重要度只允许做同分平局裁决。
4. **空结果合法**：所有通道全空时返回 `{results:[], note:"没有找到相关记忆"}`，绝不硬凑。
5. category 过滤在通道内做（读侧把 legacy `daily` 归一成 `semantic`，见批2）。

### 1.2 藤蔓扩展规则（治搭车泛滥）

- 种子 = **过了垃圾线的直接命中前 3 名**，仅此。
- 只扩 1 跳（Emet 规模不需要 2 跳）。
- 每条藤蔓命中的通道内排序 = (父命中名次, 边强度)；**总量上限 5 条**。
- 边强度：手工连的藤蔓记 0.9；自动关联记创建时相似度（批2 重织时回填）；**未经确认的自动关联不参与扩展**（confirmed 字段见批2）。
- 返回结构里藤蔓命中标注 `via_link` 来源（现有字段保留），前端/模型可见它是"联想"不是"直接命中"。

### 1.3 recall 的 vault 层补垃圾线

`mem2SearchL1`：向量道候选 **dist≥0.50 丢弃 + best+0.12 相对窗**（把 `mem2BuildInjection` 里现成的后置过滤搬进来，FTS-only 命中保留）；L1 摘录道（Vectorize 查询）同样过滤。全空时 recall 返回「没有找到相关记忆」。垃圾命中不再计 access（只有过线命中才 `logAccess`）。

### 1.4 双时间戳（治富者愈富）

- 新字段 `last_recalled_at`；检索/读取/连线**一律不再写 `updated_at`**（grep 所有 `updated_at = now()` 的检索路径：语义命中、exact 命中、memory_get、memory_link、织藤 backfill）。
- `calcRecency` 保持读 updated_at（现在只反映真实编辑）；归档清扫改用 `last_recalled_at || updated_at`。
- `activations` 保留但**只对最终返回给调用方的命中 +1**，且不参与任何排序。

### 1.5 字面通道（literal lane）+ 两字词解锁

- 查询 ≤20 字符且含专名特征（引号内词、2-8 字中文块、ASCII token≥3）时，并行跑逐字匹配，**不受向量分数否决**，作为 `keyword` 通道的一部分参与 RRF。
- recall exact 的 trigram ≥3 字限制补两字词后备：2 字查询 → vault 端 KV 子串扫描（185 条，便宜）+ D1 `archive_windows` 近 180 天 `LIKE '%X%'` LIMIT 50。给 recall 工具描述补一句两字可用（描述改动合并到本批唯一一次部署）。

### 1.6 时间词处理

- 查询含 最近/最新/现在/今天/昨天/刚才/上周/这几天 → 从送 embed 的文本中剥离，转为融合后新近度加成：≤1 天 +0.25 / ≤7 天 +0.18 / ≤30 天 +0.10（加在最终分上，封顶 0.25）。
- recall 的 `after/before` 过滤**同样作用于 vault/L1 层**（现在只管 archive）。

### 1.7 琐碎消息门（省额度）

`/api/mem2/inject` 入口：消息 ≤2 字符，或在白名单 {嗯, 嗯嗯, 哦, 噢, 好, 好的, ok, OK, 收到, 继续, 哈哈, 哈哈哈, 纯 emoji} → 直接返回空注入（不 embed、不查 Vectorize）。**晚安/早安不进白名单**（仪式性消息要带记忆）。跳过时在 recall_trace 记一行 `floors:"trivial_skip"`。

### 1.8 向量可靠性

- `memory_save`/`memory_update` 的 `vectorUpsert` 改为 **await**，失败在记忆对象上记 `vec_status:'failed'`（成功清除该字段）；`move_item` 转正记忆补上同样的 embed。
- cron（:30 拍搭车）加**补漏扫描**：找 `vec_status:'failed'` 或无 `vec:` 键的 `mem:` 行，每拍补 ≤25 条。
- **删除记忆/作废 L1 时同步删对应向量**（KV `vec:` 键 / Vectorize deleteByIds ≤100 切片）——僵尸记忆不得从 ANN 复活。

### 1.9 卫生

- 落盘与返回时剥掉**全部 `_` 前缀字段**（化石 `_score`、`_scoreB` 等一并绝迹）；真实排序分以 `score` 字段明示返回。
- `breath` 返回同样过 strip。
- `arousal: args.arousal ?? 0.5`（修 `||` 吞 0）；`memory_list` 的 `total` 在 slice 前计算。
- `memory_save`/`diary_write` 后同步 vault FTS（调 `mem2VaultSync` 的单条版或挂 cron）。
- 本批所有 TOOLS 描述更新（memory_search 描述里删掉"重要度加权"旧说明）一次性部署。
