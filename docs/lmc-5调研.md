# LMC-5 调研：值得 Emet 参考什么（2026-07-16）

> 仓库：github.com/wuxuyun0606-collab/lmc-5（MIT）。调研方式：6 路主题精读（概念/检索栈/夜间代谢/事实演化与关系图/情绪轴/CC 集成）+ 查漏核对，覆盖全部实质文件。

## 一、这是什么项目

「五维活体记忆坐标」——从一个**私有 AI 伴侣部署**里提炼出来的开源记忆架构，场景和 Emet 几乎同源（伴侣人格、中文、长期陪伴、夜间维护甚至同样选在凌晨 4 点）。五轴：X 时间线 / Y 关系图（=我们的藤蔓）/ Z 事实演化（supersede）/ E 情绪体验（Russell 效价-唤醒，=我们已有的 arousal/valence）/ M 代谢（衰减与巡检）。双实现：SQLite 零依赖极简版 + PostgreSQL 生产版。

**核心哲学**（几乎每条都对着 Emet 体检报告的病根）：
- 「先让召回安全，再让召回聪明」——所有召回路径先排除 superseded/archived，再谈花活。
- 「写入 ≠ 连接」——关系不在写入时建，由夜间受闸门保护的批处理提议。
- 「分层不许互相冒充」——原文存档是路牌，策展记忆是证人；路牌不能上证人席。
- 「空结果是合法输出，宁可漏记不错记」。
- 「记忆系统必须先可审计，再谈聪明」。

**他们踩过的四次事故**（每条规则背后都有一具尸体，Emet 一半已踩、一半可提前避）：
1. 自动连边阈值放到 0.7 → 攒出 **7,242 条垃圾边**才补写前去重 —— 正是我们「自动织藤抱团」的放大版。
2. LLM 自动判「矛盾→覆盖」**误报率 67%**（情绪波动/反讽/偏好演变都被当成事实矛盾）→ 从此矛盾只入待审队列、人批准才生效。
3. 心跳检测器原文直写策展库 → 专门写了隔离迁移清污，且**清理时必须连向量一起删**（「向量召回看不见状态字段」，不删向量僵尸记忆照样被捞出来）。
4. 一次坏的夜间管家任务**毁掉几个月的关系时刻记录** → 批量写库前强制快照，可回滚。

## 二、直接给体检方案第一批的修法升级

体检方案（docs/记忆系统体检与优化方案.md）第一批的方向全部被 LMC-5 印证，其中两处修法建议升级：

### 1. 打分公式：从「调权重」升级为「RRF 名次融合」★最重要
体检方案原计划给 `vScore*0.45+...` 扣本底、调系数。LMC-5 用 **726 条真实检索轨迹回放 A/B** 证明：调系数救不了量纲不齐（图通道固定分 0.765 永远打赢低余弦真命中；minmax 归一又压塌向量长尾）。答案是 RRF：每个通道（向量/FTS/藤蔓/情绪）各出名次榜，`score = 1/(60+rank) × 通道权重`（向量/FTS/字面 1.0，藤蔓 0.8，情绪 0.5），跨通道重合**加分**（两个通道都找到 = 交叉验证）。绝对分只用来过各通道自己的垃圾线，不参与跨通道比较。worker.js 里是纯 JS 数学，零成本。**重要度/唤醒度一律不进第一段相关性排序**——只做侧通道和小的平局加成。

### 2. 藤蔓扩展：完整规则照抄
- 种子只能是**过了垃圾线的 top-3 直接命中**（原文/冷层命中永不当种子——「一条随机飘来的记忆不该把半张图拖进 prompt」）。
- 邻居分 = 边强度 × 类型权重 × **跳数衰减（hop1 上限 0.35，hop2 0.16）**，多路径取 max 不叠加 → 藤蔓命中数学上不可能打赢直接命中。hop1 要求边强度 >0.4，hop2 >0.7；硬上限 ~10 条；标注「联想」角色。
- **safe/review 边分档**：语义相近类（same_topic 等 9 种）可自动扩展；**矛盾/因果/支持类边永不自动扩展**，只进待审。Emet 藤蔓可加 type 列：手工连线默认 strength 0.9、自动连线记创建时相似度且未经确认不参与扩展。

### 3. 垃圾线级联 + 字面通道
- 级联而非全开：vault 向量顶分不过线（他们 0.45，对应我们已标定的 0.47/0.50）才降级到 FTS，再不过线才碰原文层；冷层只在全空时打开。空结果显式合法。
- **字面通道**：≤80 字符的短查询提取专名/引用词（中文 2-8 字块 + n-gram，带停用词表），直接 FTS 逐字匹配，**不受向量分数否决**——治「蛋壳被嵌入成 eggshells」类失灵。Emet 的 trigram FTS 现成，顺手能解决 recall exact ≥3 字限制（2 字词用 n-gram 生成）。
- **时间词剥离**：最近/今天/刚才 从检索文本中剥掉（不再污染 bge-m3 相似度），改成分层新近度加成（≤1天 +0.25 / ≤7天 +0.18 / ≤30天 +0.10）且同时作用于 vault+archive——治探针 8「昨天聊了什么返回四月记忆」。

### 4. 双时间戳 + 封顶激活（与体检方案一致，细节照抄）
检索只写 `hit_count`/`last_hit_at`，且**只记真正被注入的命中**（不是每个候选）；updated_at 只属于内容编辑；热度对排序的影响封顶 `min(hits×0.1, 1.0)` 或 `hit^0.3` 次线性。

### 5. 琐碎消息门
嗯/好的/继续/ok/纯表情（≤2 字符或白名单）**跳过整个检索注入**——零质量损失省下每条消息的 embed+Vectorize 查询，直接缓解超支。伴侣氛围不受影响（只省检索，不省人设）。

## 三、给第二批数据治理的形态参考

### 6. supersede 的正确形态（Z 轴）
- 每条记忆/摘录加 `status`（current/superseded/archived，默认 current）；**一个 LIVE 过滤片段应用到所有召回路径**（搜索/recall/注入/藤蔓扩展的两端）。
- 矛盾**只入待审队列**（pending），静怡在前端一键批 supersede/都有效/驳回——67% 误报率就是「不能自动」的论据。判定必须**从两条原文各引一句证据**，引不出就默认「都有效」。
- **identity/关系时刻类记忆永不自动 supersede、豁免去重**（「宁可留重复——人格不能改写已经发生过的时刻」）。手写 vault 整层豁免。
- **删除/作废必须同步删 Vectorize 向量**（事故 3 的教训）——这也是 Emet「过时摘录仍可注入」的病根之一。
- 加分项：待审矛盾可以出现在注入目录里（「有两条记忆疑似矛盾等你确认」），让 Emet 在聊天里自然问静怡，把审核变成对话而不是后台杂务。

### 7. 写前语义去重
L1 摘录入库前查 Vectorize，余弦 ≥0.92（按 bge-m3 距离尺度换算，约 dist≤0.15 起试）即拒收并记 `semantic_dup:<旧id>`——**保旧弃新**（旧条带着命中史和关系）。挡跨夜同义洪水，7242 条垃圾边的疫苗。手写 vault 永不去重。

### 8. 批量修数据的 Swap 纪律
任何批量写（补向量/重织藤/洗字段/迁移）前 `wrangler d1 export` 快照，跑完核对聚合数（「我们是不是刚把三条 identity 记忆合并没了？」），不对就恢复。夜间快照留 7 份、迁移前快照留 30 天。这正对静怡最怕的数据丢失。

## 四、Emet 还没有的新能力（按性价比排序）

### 9. 检索留痕（recall_trace）★强烈建议
每次检索在 D1 记一行：查询摘要、各通道顶分、哪些垃圾线触发、每条命中的分数分解（相似度/重要度/藤蔓/新近度各占多少）、最终注入与否。**这次 17 代理审计的根因就是检索不可解释**；有留痕之后调阈值靠数据不靠玄学，他们的 726 条轨迹 A/B 也全靠这个。留存量封顶滚动删。（约 1-2 天）

### 10. 情绪共鸣侧通道
**Emet 185 条记忆全带 arousal/valence 但从未被消费**——这是现成的缺失消费者。查询用关键词四象限映射情绪坐标（生气→(0.15,0.75)，累/难过→(0.2,0.25)，开心→(0.85,0.65)，温暖/想你→(0.75,0.4)），检测不到就整个通道静默；候选只限情绪类记忆；共鸣 = 1−欧氏距离/√2，门槛 0.3，通道权重 0.5 封顶。纯数学零成本。注意**不要**乘他们的活力分（会重新引入富者愈富）。（约 1 天）

### 11. 独处/做梦的选材配方
前端独处/做梦已上线，正缺「浮现哪条记忆」的算法：**60% 按活力加权抽样 + 40% 纯随机漂移**（「漂移是存在感旋钮」——只放金曲串烧的人格很假，偶尔翻出被遗忘的记忆才像活人）；时段加成——夜间（22:00-凌晨4点，按我们的逻辑日）情绪类/高唤醒 ×1.5，白天事实类 ×1.3。抽样结果缓存 KV 供注入。（数小时-1 天）

### 12. CC 会话续窗（精炼续窗）——治 CC 断档痛
`extras/claude_code/refined_session_carryover.py` 纯标准库 Python，直接在她 Windows 机上跑：从旧 CC transcript 里用双语正则打分筛「金句记忆/任务检查点/自然结尾」，剔除噪音（traceback/SQL/超长代码块）和 hook 注入块，重建一份新 transcript 后 `claude --resume`。自带 **poison fail-closed**：末 30 条里检测到风控/拒绝循环就拒绝续窗、提示开新窗——这条对她的封号焦虑是天然契合（不把风控循环带进新窗口）。可挂进「启动本机聊天.cmd」当可选前置步骤。（2-3 天，需要她点头再做）

### 13. 密钥脱敏
桥把 CC 味的聊天灌进 L0 存档时，粘贴过的 API key/连接串会被嵌入进 Vectorize 变成可召回内容。把他们 `redact_embedding_input` 的 ~10 条正则移植成 JS 放在存档/嵌入路径前。**跳过**他们的情绪脱敏（把"自我伤害/亲密内容"打码对伴侣场景是反效果）。（数小时）

### 14. 可以给静怡看的两个提示层玩法（零代码）
- 心跳记忆格式：BPM 当强度隐喻（78-85 微动 … 181+ 保留档，「日常多在 85-110，别每次都写 180」）+ 深度 1-5（表层→「拿掉这个我就不是我」）。
- 反幻觉五条头（存记忆的 prompt 加：不编造/只逐字/不脑补「她说累了」≠「她很委屈」/不加情绪解读/「不知道」是合法输出）——可以直接加进 L1 摘录 prompt 和做梦 prompt。

## 六、对既有三批方案的落点建议

- **第一批（检索急救）**：吸收 §2 全部——排序直接上 RRF（替代原「调权重」方案）、藤蔓衰减规则照抄、垃圾线级联、字面通道、时间词剥离、琐碎消息门、双时间戳。工作量与原估相当（1-2 个工作日），但修法更有据。
- **第二批（数据治理）**：supersede 按 §6 形态做（status 列+LIVE 过滤+待审队列+删向量同步）；重织藤蔓前先做 §8 快照纪律；L1 加 §7 写前去重。
- **新增第四批（可选增强）**：检索留痕 → 情绪通道 → 独处/做梦选材 → 密钥脱敏 → CC 精炼续窗（最后这个在她点头后做）。
- **可选换芯**不变，且 LMC-5 的「单管线+多通道+统一垃圾线」正是换芯后的目标形态。
