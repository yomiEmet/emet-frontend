## 一、现状（已完成的地基，别动）

手机已能通过 **`https://emethome.com`** 聊本机 `claude -p`：
- Cloudflare 命名隧道（`emet-bridge`）把 emethome.com → 本机 `127.0.0.1:8000`（桥）。
- **Cloudflare Access 用静怡邮箱验证码锁死**——陌生访问被弹登录页（外部实测 `auth_status: NONE`）。桥只听 127.0.0.1，带 `Cf-Access-Authenticated-User-Email` 头的请求只可能来自被 Access 验过的隧道，故桥放行、手机无需暗号。
- 这不是"裸暴露隧道"，是"隧道 + Access 邮箱锁"。安全性与信箱模式同级。

**"直连"术语澄清**（静怡问过，务必对齐）：现在手机走的是 **隧道直连**——数据穿隧道直达桥（能 SSE 流式），前面有 Access 挡门。它和"信箱模式(relay，中转 KV 存一下)"的区别只是**数据路径**，二者**都不暴露公网**。换成直连的唯一目的：**信箱模式不能流式**，直连能逐字冒 + 出思考链。

## 五、需要静怡拍板的决策（4.8 别自作主张，先问）

1. **`--effort high` 的代价**：high 才有思考，但**更慢、更烧订阅额度**（思考 token + 回复更长更慢）。选项：(a) 全程 high；(b) 加开关（日常低、要思考时高）。**建议先全程 high 试用，嫌慢/费再降。**
2. **思考链默认展开还是折叠**：现在是 details 折叠（收起）。保持收起，还是默认展开？
3. **信箱路径要不要也带思考**：手机走隧道直连有思考；万一隧道没开掉回信箱，就只有文本没思考。给信箱加思考成本较高（worker KV 多存一路 + 复杂度）。**建议暂不做**，隧道是主路径。

## 六、风险 / 坑清单

- `--verbose` 是 `-p` 下 stream-json 的**必需项**，别删。
- `--effort high` 是思考的**开关**，删了就没思考。
- `readBody` 的 `Buffer.concat` 是真修复，**别回退**到 `buf += chunk`。
- 隔离 cwd 防串味，**别把 cwd 改回项目目录**。
- 合规不变：全程本机 `claude -p` + 静怡本机登录，A 社视角与桌面用 CC 一致；Access 只认静怡邮箱。**不要引入任何"把订阅凭证交给第三方"的路径。**
- **测试禁忌**：git-bash 的 `curl` 发中文 = GBK 乱码假 bug。只用 Node/浏览器/手机测。
