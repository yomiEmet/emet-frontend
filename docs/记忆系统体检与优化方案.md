# Emet 记忆系统体检报告与优化方案（2026-07-15）

> 审计方式：17 个并行子代理——5 路审计（vault 检索代码 / mem2 存档层 / 前端注入链路 / 12 项线上检索探针 / D1+KV+Vectorize 生产数据体检）+ 12 条关键发现逐条对照代码反方核验。所有行号对应 emet-memory 仓库 commit abbad84 时的 worker.js（8546 行）。

## 一、总体结论

骨架是好的：**recall 双层检索（vault+archive）、L0 存档管道、L1 摘录、cron 都健康**。坏的是 `memory_search` 语义检索这条主干道（12 项探针里它包揽了主要失败），外加向量额度超支 3 倍、约 1/3 手写记忆缺向量两个数据问题。建议"先修表、后换芯"，不推倒重来。

## 三、已核实的病根（全部经代码反方核验，标注 CONFIRMED/PARTIAL）

### 高严重度

1. **藤蔓搭车（via_link 扩展）完全不看查询** — CONFIRMED
   worker.js:973-983。搭车分 = `(importance/10)*0.5 + recency*0.5` 再 ×0.6，**不含任何查询相关项**，且与直接命中同池排序抢 limit 名额。新鲜的重要度 10 邻居恒得 0.6，打赢几乎所有真实语义命中（典型 0.35-0.55）。重要度 10 核心记忆间又有密集"自动关联"抱团 → 一个命中拖进全家桶。这是探针 1 的主因。
   修法：搭车分改为父命中分×0.6 继承；限 2-3 条；或放独立 related 栏不占名额。

2. **打分公式相似度权重不足且无本底扣除** — CONFIRMED
   worker.js:94：`vScore*0.45 + kScore*0.15 + tScore*0.15 + rScore*0.15 + iScore*0.1`。bge-m3 无关中文余弦本底 ~0.5（自家标定注释 worker.js:6687 佐证），无关+新鲜+重要度10 ≈ 0.475 > 对题+60天+重要度3 ≈ 0.45。代码注释自认症状（7 月加 exact 就是因为"代理7897"被封号记忆淹没）。
   修法：`max(0,(cos-0.45)/0.55)` 归一化后设垃圾线，过线才进候选；重要度/新近度降为小加成或平局裁决；空结果显式返回"没有找到"。

3. **每次检索都刷新 updated_at → 越被搜越靠前的死循环** — CONFIRMED
   worker.js:990-991（语义）、942-943（exact）、1057-1058（memory_get）都写 `updated_at=now()`；calcRecency(:55) 读的正是它（直接搜索占 0.15、搭车分占 0.5）。还顺带弄坏归档清扫（:312 按 updated_at 判陈旧——被搜过的永不归档）。mem2 那边是对的（分离 last_accessed/access_count，:6845）。
   修法：加 last_recalled_at 字段承接激活记录，updated_at 只在内容编辑时动；连线操作（memory_link :1101-1102）也停止刷新 updated_at。

4. **recall 的 vault 层没有距离垃圾线** — CONFIRMED
   worker.js:1024 → mem2SearchL1(:6768)：向量道全量入候选（:6778-6784）、摘录道同样不过滤（:6796-6803），RRF 按名次+slice(0,n)（:6835）保证任何查询必返回 n 条。对照：archive 层有 0.47 线（:6740-6742），注入通道有 0.50 硬线+best+0.12 相对窗（:6866-6874）——唯独 recall/search 直连裸奔。垃圾命中还计 access 写 recall_log（:6837-6852）轻度自我强化。
   修法：把注入通道现成的过滤搬进 mem2SearchL1（FTS-only 命中保留），空了返回"没有找到相关记忆"。

5. **向量写入发射后不管；move_item 路径根本不写向量** — CONFIRMED
   worker.js:916 `vectorUpsert(...)` 不 await、失败静默（:29-34 返回 false 被忽略）；memory_update:1081 同病；move_item 转正记忆（:1441-1443）完全没有 vectorUpsert。**实测后果：KV 里 vec:\* 只有 118 个键，对 185 条记忆 ≥67 条无向量**（星图 118 节点对上了）——无向量 = 语义搜索里 45% 权重归零、织藤 backfill 与星图除名。唯一修复通道是手动 /api/migrate-vectors(:126-146)。
   修法：await + 失败落 vec_status 字段；move_item 补 embed；加巡检补漏；先手动跑一次 migrate-vectors。

### 中严重度

6. **自动织藤 0.50 阈值 = 噪音本底，连线实际由标签决定** — CONFIRMED
   worker.js:897（≥0.50 取 3 条）；打分 :205 `v*0.55+tScore*0.45`。无关文本余弦 ~0.5 自带 0.275，两个偏门共享标签即过线；无共享标签则需余弦 ≥0.909（几乎不可能）→ **自动关联基本 = 标签连线**。织藤还刷 updated_at（:910,:564）让抱团成员永远"新鲜"，直接喂养病根 1。backfill(:479-567) 同阈值全库适用。
   修法：自动连线加"裸余弦 ≥0.6"硬条件；连线不再刷 updated_at。

7. **weave_candidates 无下限，无关时输出 8 条 0.15 分噪音** — CONFIRMED（自动连线污染指控不成立：两条自动关联路径都有 ≥0.50 过滤，0.15 噪音不会被自动连上；只污染给模型看的建议）
   worker.js:202-208 无共享标签分支 `v*0.3`+slice 无过滤，handler(:1122-1125) 还附鼓励连线的 hint。
   修法：设下限（如 <0.35 丢弃）+ 空结果显式"没有相关记忆"。

8. **化石 _score 字段永生，真实分数反被剥掉** — CONFIRMED
   现行代码与全部 57 个 commit 都不写 `_score`（只有 _scoreA/_scoreB），但 KV 里的史前对象带着 0.9-11.4 的旧衰减分；每次激活提升整体重写 → 化石永续；剥字段只剥 _scoreA/_viaLinkFrom（:992/:999），memory_get(:1057-1060) 与 breath(:1319-1322，另漏 _scoreB) 原样吐出。调试时看到的"分数"全是幻觉。
   修法：落盘与返回时剥掉全部 `_` 前缀字段；真实分以 `score` 明示。

9. **每次语义搜索 ~370 次 KV 读 + 串行向量循环 + 至多 10 次写** — CONFIRMED
   worker.js:919-920 全量 list、:40-52 逐条串行 await 读 vec、:988-994 激活串行写。weave_candidates 与 memory_save（内部调织藤）同价。注入通道（每次发消息）同样 N+1 串行读（:6758-6763）。
   修法：向量打包成单 KV blob 或搬进 Vectorize（layer='mem'）；激活写批量/异步。

### 数据与管道体检（生产实测 2026-07-15）

- **管道健康**：cron 活着（l0-lastrun 今天 05:00），dirty/offdirty 积压 0，L1 摘录已开启且在产出（146 条，最新 07-15 03:30）；04:30 那轮 LLM 输出 JSON 解析失败（{convs:0}，extdirty 保留重试，间歇性非停摆）。
- **Vectorize 超支 3 倍**：14,751 条向量（免费线 ~4,880），7/4 时 8,778 还在涨——预算闸只装在 vecq 排水口(:6425-6427)和官方导入(:6640)，**聊天路径(:6508 无 skipVectors)和 L1 上载(:7014)绕闸直写**。vecq 队列冻结（23 条官方 conv 中途游标 + 1 条新会话）。没绑卡不会扣费，强制执行时表现为写入失败。
- **危险洞**：超额期间官方 conv 重导入会先删旧向量(:6362)再因 skipVectors 跳过重写且**不入 vecq**（:6394-6411）→ 该对话语义覆盖永久丢失、无标记。
- **D1 260MB / 500MB 免费上限（52%）**，raw FTS 90,391 行。先监控。
- **meta:official-lastrun 假报"pending_more:true"**（空跑早退不写 lastrun :6627）——体检面板会误读，宜补心跳写入。
- **L1 无 supersede**：schema 有 superseded_by 列但从未写入。实例：07-14 摘录"-p 接前端没搞定"已被 dcaace6 打脸，但它比正确记忆更新鲜、更容易被注入。
- **vault FTS 同步是手动接口**（mem2VaultSync :7074），未挂 memory_save/diary_write/cron → 新手写记忆进不了 recall 的逐字索引。

### 前端链路（次要）

- MCP callTool（mcp.js:68-79）不触发 invalidateData → 聊天里存的记忆，记忆页不刷新（唯一刷新 = 下拉）。
- chatSystemPrompt 每次发送请求 /api/health/context，client.js request() 无超时 → 挂起的 fetch 会永久堵住发送。
- api.js:555 AbortSignal.timeout 在老 iOS Safari（<16）不存在，异常被吞 → 记忆目录注入在旧设备上静默失效。
- 低危：mcp.js 头注释过时（写 5 个工具实为 14）；memory_list 的 total 在 slice 后计算；memory_save 的 arousal:0 被 `||` 吞成 0.5；daily 分类 1 条在分类过滤下永不可达；resolved 183/185 无区分度（只影响 breath/wake，resolve 会 ×0.1 雪藏——未记载的悬崖）。

## 四、优化方案

### 第一批：检索急救（worker.js，每条独立提交可回滚，约一个工作日）

1. memory_search 重排：余弦扣本底归一化 + 垃圾线，重要度/新近度降为加成；空结果显式提示。
2. 藤蔓搭车改继承分（父分×0.6）+ 限量 2-3 条或独立 related 栏。
3. recall vault 层补垃圾线（搬注入通道现成逻辑），空结果显式提示。
4. last_recalled_at 与 updated_at 分家（搜索/读取/连线均不再刷 updated_at）。
5. 织藤：weave_candidates 下限 + 空提示；自动连线加裸余弦 ≥0.6；织藤不刷 updated_at。
6. 向量补漏：await + vec_status；move_item 补 embed；手动跑 migrate-vectors 补齐缺失的 ~67 条；加巡检。
7. 卫生：剥全部 `_` 字段、真分数明示；recall 日期过滤作用于 vault；memory_save/diary_write 挂 vault FTS 同步；顺手修 arousal `||`→`??`、total 先算后切、daily 迁移。

### 第二批：数据治理（动数据，先 backup_export 全量备份，单独提交）

- 洗化石字段（_score/_scoreB 等）一次性迁移。
- 重织藤蔓：新阈值重跑 backfill，只重建"自动关联"（手工连线不动）。**清旧自动关联需静怡点头。**
- L1 最小版 supersede（先作废 07-14 那条已过时摘录）；resolved 字段去留拍板。

### 第三批：额度与容量（涉及钱，待静怡拍板）

- 路线①：Workers Paid $5/月 → 调大 MEM2_VEC_BUDGET，解冻 vecq，全量语义覆盖（2 万窗 ≈ 29M 维度基本全含）。
- 路线②：留免费 → 预算闸补到所有写入路径 + 按 date_int 裁旧官方向量回 4500 以内（只损失旧档案的语义搜索，逐字全量永在）。
- 两条路都要修"超额重导入永久丢覆盖"洞 + official-lastrun 心跳。

### 第二步（可选换芯，第一批见效后再议，估 2-3 天）

memory_search 收编进 mem2 RRF 引擎（category/importance 作后置过滤），全系统单一打分器+单一阈值组；手写向量从 KV 暴力扫描搬进 Vectorize（layer='mem'）消 N+1。收益：Emet 只有一套检索行为 + 速度；代价：改动面大。

### 前端小批（随手，独立提交）

MCP 写操作后 invalidateData；health/context 加超时；AbortSignal.timeout 兜底；mcp.js 注释更新。
